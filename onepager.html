なぜ Astra の枠は減るのが速いのか

モデルPlus・5時間あたりの目安出力100万トークンのクレジット
GPT-6 Astra5〜45通1,250
GPT-5.6 Solソル10〜100通500
GPT-5.6 Terraテラ25〜200通300
GPT-5.6 Lunaルナ250〜2,000通30
  • 目安は固定の上限ではなく、作業と設定で変わる。入出力が大きい・強さが高い・Fast mode・手数の多いタスクで消費が増える
  • 一方で Astra は、少ない出力トークンで強い結果を出し、1タスクあたりの推定コストは従来より低い、と API のモデルガイドにある

2

サブエージェントとは・いつ動くのか

親のAIが作業を分けて、子のAIに渡す仕組み。例：「先週届いた問い合わせ50件を分類して、週次レポートにまとめる」を、親が「前半の分類」「後半の分類」「集計」に分けて子に任せる。

learn.chatgpt.com/docs/agent-configuration/subagents
subagent workflows consume more tokens than comparable single-agent runs.
子は1体ずつ自分でモデルとツールを使うので、同じ仕事を1体でやるより多くトークンを使う。
  • 今の Codex では、サブエージェントの仕組みは既定でオン
  • 子のモデルと強さを決めていなければ、親の設定をそのまま引き継ぐ
  • 動き出すのは「頼んだとき」「AGENTS.md やスキルに指示があるとき」。Ultra も子を使って並列に進めるモード
  • 悪者ではない：大量の調査・テスト・要約では、メインの会話が散らからず速くなる。損をするのは軽い作業で子が並ぶとき

3

裏技①：サブエージェントを止める

# ~/.codex/config.toml [features] multi_agent = false [agents] enabled = false
  • agents.enabled は既定で true。false でマルチエージェントの機能が止まる
  • 自分で開くのが不安なら、Codex に「バックアップを取ってから、この2行を足して」と頼めばよい
  • 困ること：大量の調査を並列で速く進められない。Ultra も使わない前提。会社のアカウントでは管理者の設定が優先されることがある

4

裏技②：止めずに「子を軽く・少なく」する

# ~/.codex/config.toml [agents] default_subagent_model = "gpt-5.6-terra" default_subagent_reasoning_effort = "low" max_concurrent_threads_per_session = 2
  • 公式は、軽いサブエージェントの作業には gpt-5.6-terra を案内している
  • 子1体ぶんの出力単価は、Astra 1,250 → Terra 300 クレジット（約4分の1）
  • 依頼文でモデルや強さを指定すると、依頼文の指定が優先される

裏技③④：Light から始める・Fast mode を切る

総まとめ ＆ 今日からやること

裏技効くこと向かない場面
① 止める軽い作業で子が並ばない並列の大きな調査が遅くなる
② 子を軽く・少なく並列の良さを残して単価と数を抑える子に難しい判断をさせる作業
③ Light から考える量を最小から始める難しい1件は上げる
④ Fast を切る2.5倍の消費を避ける返事が遅くなる
⑤ 読ませる量を減らす毎回の読み込みが減る絞りすぎると推測で埋める
  • 1Ultra と Max を外し、Light（CLI は Low）にする
  • 2並列が要らなければサブエージェントを止める。要るなら子を Terra・low・2体まで
  • 3Fast mode を切る
  • 4MCP サーバーと AGENTS.md を見直す
  • 5次の同じくらいの作業で、使用状況の減り方を比べる

FAQ・注意点

止めたら、仕事が遅くならない？
並列で進める大きな調査は遅くなる。そういう作業がときどきあるなら、止めずに裏技②を。
Astra をやめて、安いモデルにすべき？
やめる必要はない。定型の作業だけ Terra・Luna に振り、難しい作業は Astra に残す。
ChatGPT Work（ブラウザ）しか使っていない
Work で設定ファイルが効くかは公式に記載なし。Ultra を選ばない・並列を頼まない・Light から始める、で同じことをする。
